# 微信好友自动定位、可见聊天读取与草稿填入

入口：侧栏「微信可见聊天」，本地开发地址 `/wechat`。

## 使用流程

1. Windows 电脑安装微信，后端安装可选扩展：显卡版 `uv sync --extra desktop --extra ocr-gpu`，CPU 版 `uv sync --extra desktop --extra ocr`，二选一，然后重启后端。模型与实测见 [OCR 配置](OCR.md)。
2. 打开并登录微信。心迹与微信使用相同运行权限。
3. 开启「微信可见聊天读取」，输入好友完整备注，选择材料所属的关系对象和目标数量（10–5000 条，默认 1000）。
4. 点击「自动回溯并读取」。心迹自动找到微信并打开好友，向下回到最新位置，再向上滚动识别历史。界面显示已读条数和画面段数，可以随时停止并保留已读部分。达到目标后返回最新消息。
5. 对照截图检查结果，选择「导入并校对分析」或「校对后生成代回复」。校对角色、文字和时间后确认。
6. 代回复复用现有模型设置和发送预览流程。需要填入时，先开启「允许确认后填入草稿」，再在草稿旁点击「核对并填入微信」。核对内容后确认填入。
7. 填入后由用户在微信检查并自行发送。此适配器不会按 Enter，也不接受自动发送参数。

## 自动定位与复用来源

用户不需要选择窗口、布局、比例、边界、长宽高或截图区域。每次使用 Windows UI Automation 返回的实时控件边界，并按截图尺寸处理 DPI 映射。窗口移动或输入框调整后不会继续使用旧坐标。操作时微信会切到前台，请暂时不要操作鼠标键盘。

复用 [Hello-Mr-Crab/pywechat（pyweixin）](https://github.com/Hello-Mr-Crab/pywechat) 的微信 4.1 控件定位信息和好友搜索筛选逻辑。参考提交 `ebe8d4be9347816d221c38843e5b9e5e480bd8fb`，原文件为 `src/pyweixin/Uielements.py`、`WeChatTools.py` 的 `Tools.get_search_result` / `Navigator.search_friend`。

适配模块 `backend/rapport/desktop/pyweixin_navigation.py` 保留 LGPL-2.1，原许可证位于同目录 `LICENSE-pyweixin.txt`。适配改为现有 Python UIAutomation 驱动，增加有界遍历、完整好友名唯一匹配及消息树隔离；没有引入原项目的发送、监听、系统设置或文件操作。分发适配模块时同时提供该模块源码、修改说明、许可证与原始源码链接。

也评估了 [wxauto](https://github.com/cluic/wxauto) 和 [wxauto4](https://github.com/fly000001/wxauto4)。后者 README 标明适配 4.0.5，未直接作为本机 4.1.13 的导航依赖。

自动滚动通过无障碍定位的消息列表滚轮完成，不要求坐标。每一段画面先核对好友，再在本机 OCR。拼接使用相邻画面的纹理重叠（OpenCV 模板匹配）和连续文字/角色/位移证据；不会全局删除内容相同的不同消息。若大步滚动无法拼接，会向下回退一步再试。仍无法验证时停止并明确标为部分结果，不猜测缺失段。

只计可识别的完整文字消息；图片、语音不计入目标条数，不后台监控。

图片和文件按像素判断，不按识别出的文字判断：消息区里与聊天背景不同的每个色块单独检查。头像是贴着左右边缘的小方块；文件卡片的文件名下面有一行大小（如 `467.8K`）；图片是没有文字的大色块、颜色不成单一气泡色的色块，或其中文字比正常聊天字小得多的色块（手机截图）。这些色块里识别出的文字一律丢弃，不当作聊天内容；图片和文件以占位消息 `[图片]`、`[文件] 文件名` 保留在原位置，发送者取所在的一侧。占位不计入目标条数，结果统计里单独列出图片、文件数量和被丢弃的文字处数。归档时占位生成「原件缺失」的媒体资产，之后可以补原件。回复绑定与发送回执只比较文字消息，发出一张图片不会被当成文字上下文变化。

实测（2026-09-28，一张真实的最新画面）：改动前，图片里的文字和一张文件卡片被读成 9 条“消息”（8 条算作我方，1 条发送者未知）；改动后，这一画面得到 2 个图片占位（我方）、1 个文件占位（对方），丢弃图片、卡片和头像内的 33 处文字，没有误读的文字消息。多次滚动无变化表示「未加载更多历史」，不宣称已覆盖全部微信历史。单次上限 6000 段画面或 2 小时。切换窗口、好友变化、遮挡、退出页面或点击停止会停止任务；关闭功能、清空数据、删除关系会撤销任务。

好友按完整名称匹配；同名多个结果停止，请为目标好友设置唯一备注。搜索只使用联系人/最近使用分组，排除聊天记录、群聊、网络搜索及添加好友入口。

### 时间与统计

结果包括我方/对方/待校对条数、字符数、画面数量、排除的重叠识别次数、时间覆盖和相邻消息间隔中位数。时间标签保留在每条消息的 `meta.time_label` 中。

微信只在停顿之后的第一条消息上方显示时间。读取时以当时的日期为锚点换算每个标签：今天只显示 `HH:MM`，`昨天 HH:MM`，一周内显示 `星期X HH:MM`，今年更早显示 `M月D日 HH:MM`，往年显示完整日期。换算不自洽的标签（例如落在读取时刻之后的时间、指向今天或昨天的星期）不用。同一标签下的消息都带这个标签的时间，精度记为 `label`：可以排序、按日期归档，**不参与**间隔统计。只有完整日期标签下的第一条消息记为分钟精度。只有相邻两条都有明确时间且时间顺序有效才计算间隔；样本不足显示「暂不计算」。

拼接时的纹理重叠改为八条横带投票，多数一致（相差不超过 2 像素）才采用，单条带子上的动图或正在加载的缩略图不再否决整段；持平或没有多数时照旧停止。滚动步长按上一段实测位移自动调整到约四成画面；大步拼接失败时退回到离上一段只差一格的位置再试，仍不能验证才停止。画面像素因动图而变化、但文字和位置不变时，也判定为「未加载更多历史」。第一个标签之上的几条消息没有时间，归档时跳过。

用户可以分页校对结果，再导入现有分析流程。长历史的回复绑定使用开始读取时最新画面的摘要，避免将整段历史与单屏上下文比较而导致所有填入失败；新消息或会话变化仍会阻止填入。

实机验证版本为 **微信 4.1.13.12**。其他版本的控件支持仍需验证；UIA 树不可用时显示明确错误，不要求用户配置坐标。

失败时的行为（2026-09-27 起，已有单测，尚待实机）：没有运行微信报 `wechat_not_running`；只有登录窗口报 `wechat_login_required`；刚恢复的窗口控件树为空时最多等待 10 秒再报错；长读取途中出现 UIA/COM 异常时以 `wechat_window_unavailable` 结束，已拼接的部分作为部分结果保留，不再整批丢弃；最小化的窗口在核对窗口与进程身份后先恢复。

## 实现边界

- Windows UI Automation 用于定位微信窗口及输入框，聊天内容来自窗口截图和本地 RapidOCR，不注入客户端、不抓取消息控件树；结构化读取走数据库路径，见 docs/WECHAT-DATABASE.md。
- 仅支持 `WeChat.exe` / `Weixin.exe` 窗口。选择绑定窗口句柄和进程编号，每次操作重新核对。
- 本机 Qt 微信使用 PrintWindow 得到黑色内容，因此使用无障碍定位后的前台可见屏幕像素，并检查前台与遮挡。截图之后再次核对布局；遮挡或移动时停止。
- 好友身份优先用无障碍接口的标题文字控件名称与聊天输入框的收件人名称双重精确核对；两者都匹配时不再让标题 OCR 否决，避免生僻字误识别（例如「娈」被读成「变」）。任何非空权威名称冲突都停止，不作模糊或近形字放行。标题名称缺失时才对标题文字控件截图 OCR，小字号自动补边放大。正文继续使用截图 OCR，不读取消息控件正文。核对覆盖截图前后、OCR 完成后及每次滚动。
- 激活窗口失败时使用临时置顶和经过窗口归属校验的标题栏点击，随后恢复原置顶状态。
- 新功能默认关闭。所有接口沿用现有配对会话和 CSRF 验证。
- 截图只保留在请求与页面内存，不主动写入磁盘。识别结果先放在有容量上限的内存票据中；只有点击导入才进入现有加密材料存储。后续 AI 请求仍沿用项目原有的内容预览与确认机制，本地 OCR 本身不上传聊天。
- 票据有效期 10 分钟，最多 8 份，绑定浏览器会话和关系对象；过期票据拒绝使用，在访问和新增时清理。关闭读取、删除关系或清空数据会撤销相应票据。
- 历史读取在同一原生线程中执行，提供带配对与 CSRF 保护的启动、进度和停止接口。最多一个运行任务、最多四份任务结果；结果保存在内存并在完成 30 分钟后不可访问。好友填入票据在整个读取完成后开始计时。
- 填入要求对应材料已校对确认。执行前重新核对标题、可见上下文、输入框为空及焦点；变化时停止。填入尝试一次即消耗票据，无法确认结果时不自动重试。
- 操作日志仅记录操作类型、字符数和成功状态，不记录好友名、截图或回复正文。

## 验证

`backend/tests/test_wechat_visual.py` 覆盖标题、裁剪、角色、票据隔离/过期、配对和 CSRF、显式导入、校对前置、上下文变化、焦点、重复填入及撤销。

`backend/tests/test_wechat_navigation.py` 覆盖自动控件定位、搜索分组、同名好友、多账号、错误焦点、消息树不读取、搜索面板拦截及 DPI 边界映射。

已在本机真实微信对用户指定好友验证搜索、自动定位和读取。测试不发送消息，不替用户确认导入。

历史功能新增 `backend/tests/test_wechat_history.py`：1000 条多屏拼接与裁剪、重复短句保留、图片纹理重叠、模糊边界停止、时间来源、取消与撤销、进度接口和作用域。实机小样本已通过 11 段画面累计读取 20 条并返回最新位置；1000 条完整目标用合成画面序列验证。

实现依据：[Windows UI Automation 线程要求](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)、[Pillow 窗口截图](https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html)、[Python UIAutomation](https://github.com/yinkaisheng/Python-UIAutomation-for-Windows)。
