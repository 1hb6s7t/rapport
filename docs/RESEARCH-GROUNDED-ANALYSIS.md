# 关系分析模块：论文依据、复用选型与复现方案

核验日期：2026-09-22。状态：已完成研究选型与来源/许可核验；本轮未训练候选模型、未复现论文指标、未上传私人聊天、未替换线上判断算法。

目标：将现有「人工词表、固定阈值、通用模型提示」升级为可追溯、可复现、可独立评测的分析模块。论文是方法依据，中文微信的可靠性由本项目的验证结果决定。

## 1. 先区分四种产品输出

| 输出 | 可以验证的目标 | 不应混称为 |
|---|---|---|
| 互动行为 | 主动开启、轮次平衡、有效回应、邀约及回应、话题承接、可可靠测得的延迟 | 对方内心有多喜欢用户 |
| 情绪与沟通意图 | 话语表达出的情绪、请求、拒绝、玩笑、安慰等，支持多标签和不确定 | 已经读取到当事人真实心理 |
| 趋势变化 | 某些可观察行为相对于自身基线的持续变化及发生区间 | 关系未来必然走向 |
| 关系解释/阶段 | 结合上述证据、用户确认和可选回访问卷的解释性判断 | 经临床或心理测量认证的恋爱进度 |

原始读取与校对、缺失时间标注、好友隔离仍是基础条件。不能用采集时间代替消息发送时间，也不能把未解读的语音、图片当作没有回应。

## 2. 优先候选

### A. DialogueGCN：说话人上下文情绪模型

- 正式论文：EMNLP-IJCNLP 2019，[ACL 论文](https://aclanthology.org/D19-1015/)。
- 方法：消息作为节点，区分说话人及上下文方向，使模型考虑双方怎样相互影响。
- 作者代码：[DialogueGCN](https://github.com/declare-lab/conv-emotion/tree/master/DialogueGCN)；父仓库 [MIT 许可证](https://github.com/declare-lab/conv-emotion/blob/master/LICENSE)。
- 原实验主要为英文 IEMOCAP、MELD、AVEC，不能继承为中文微信准确率。
- 选型结论：作为可复现的说话人上下文基线，与中文编码器分类基线、当前大模型方法同条件比较。适配中文编码器后属于改造实验，不再冒充原配置复现。
- 实时回复测试必须屏蔽未来消息；离线复盘可用后文，但两者成绩分别报告。

### B. CPED / M3ED：中文数据与标签设计

- [CPED 论文](https://arxiv.org/abs/2205.14727)（2022 预印本）、[作者仓库](https://github.com/scutcyr/CPED)、[Apache-2.0 许可证](https://github.com/scutcyr/CPED/blob/main/LICENSE)。约 1.2 万段中文影视对话、13.3 万条话语，提供情绪、对话行为等标注，可用来设计中文任务和初始基线。
- [M3ED 论文](https://aclanthology.org/2022.acl-long.391/)（ACL 2022）、[作者仓库](https://github.com/AIM3-RUC/RUCM3ED)：990 段双人对话、24,449 条话语，可作中文外部评测候选；本次未核实仓库的明确许可证，暂不直接打包数据。
- 选型结论：公开中文数据用于起步和外部对照，另建中文微信验证集。影视表演不同于私人聊天，人物标签不是现实用户的心理测量；仓库许可证与影视原素材使用范围分别核实。

### C. RECCON：情绪触发证据抽取

- 论文：[Recognizing Emotion Cause in Conversations](https://arxiv.org/abs/2012.11820)，Cognitive Computation 2021。
- 数据任务是话语与原因片段配对、原因片段抽取，而非实验识别真实心理因果。
- [作者独立仓库](https://github.com/declare-lab/RECCON)未查到明确许可证；同作者 [MIT 仓库中的相关实现](https://github.com/declare-lab/conv-emotion/tree/master/emotion-cause-extraction)可按具体文件核验后考虑复用。
- 选型结论：增加「情绪判断 → 哪句原文触发该解释 → 支持/反证 → 无法确定」的独立证据模块。避免只验证引用 ID 存在，却不验证语义支持。

### D. ConvoKit 与中文礼貌特征：互动行为

- [ConvoKit 论文](https://aclanthology.org/2020.sigdial-1.8/)（SIGDIAL 2020）、[Cornell 官方仓库](https://github.com/CornellNLP/ConvoKit)，核心 MIT。
- 提供说话人/对话结构、语言协调、礼貌策略等模块。
- [CSCW 2020 跨文化礼貌研究](https://arxiv.org/abs/2008.02449)使用各 5,300 条中文微博和英文 Twitter；ConvoKit 已有 [politeness_cscw_zh](https://convokit.cornell.edu/documentation/politenessStrategies.html)。
- 选型结论：优先复用中文礼貌和对话结构的可解释特征，与统计指标结合。英文功能词协调指标必须做中文适配。礼貌不能直接解释为喜欢，论文里的微博成绩也不作为微信成绩。

### E. ruptures：长期趋势与变化点

- [方法综述](https://arxiv.org/abs/1801.00718)，Signal Processing 2020；[作者项目](https://github.com/deepcharles/ruptures)，BSD-2-Clause。
- 可复用 PELT、核变化点等离线方法，分析多变量互动序列何时发生持续改变。
- 选型结论：替换单纯按前后两组均值差固定阈值判升降的方案。先输出主动发起、有效回应、互动平衡等的变化，再由解释层讨论可能原因。
- 必须处理个人基线、时间缺失、夜间/工作日差异、数据量和异常值。检测到变化不等于证明感情变差；无可靠时间时只给顺序变化，不冒充日/周趋势。

### F. 置信度校准

- [On Calibration of Modern Neural Networks](https://proceedings.mlr.press/v70/guo17a.html)，ICML 2017。
- [作者示例代码](https://github.com/gpleiss/temperature_scaling)为 MIT，但已声明多年未维护；可参考方法，工程实现优先采用维护中的校准工具，如 [scikit-learn 校准模块](https://scikit-learn.org/stable/modules/calibration.html)。
- 选型结论：对有 logits/概率输出的本地分类器，在独立校准集上评估温度缩放等方法；绘制可靠性图并报告误差。外部 API 自报「高置信」不直接当概率，使用标注集回测和拒判策略。
- 校准改善概率解释，不创造缺失证据，也不保证跨领域仍可靠。

## 3. 值得参考、但不直接照搬的研究

**InstructERC**：[论文](https://arxiv.org/abs/2309.11911)、[作者仓库](https://github.com/LIN-SHANG/InstructERC)。核验到的作者材料为 2023 预印本、2024 v6；本次未核实正式出版 venue 或明确代码许可。其上下文、说话人、多任务与检索样例设计值得参考，但改写提示词不能继承原论文成绩。原训练规模也不能直接承诺可在本机 8 GB 显卡复现。

**吸引力预测研究**：[Large language models can detect verbal indicators of romantic attraction](https://www.nature.com/articles/s41598-026-52308-x)，Scientific Reports 2026。964 次速配约会，报告的相关系数约 r=0.12–0.23，预测力有限。可以参考其区分「真实有效线索」与「模型使用线索」的验证设计；不是长期中文微信关系阶段模型，相关系数不是准确率。数据/代码独立使用条款尚需进一步核验，不先打包进产品。

**回复时延研究**：[Templeton 等，PNAS 2022](https://doi.org/10.1073/pnas.2116915119)。面对面口语的接话间隔与连接感研究不能直接变成「微信几分钟没回就是冷淡」的阈值。使用它的思路时必须重新定义异步聊天的有效活动时段。

**关系质量验证目标**：[Joel 等，PNAS 2020](https://doi.org/10.1073/pnas.1917036117)。43 个纵向伴侣数据集、11,196 对伴侣，研究的是自陈变量与关系质量，并非微信聊天分类器。适合帮助设计用户回访和评价目标；不能据此承诺预测关系未来。

没有核实到能够直接部署、且已证明能准确判断「中文微信双方真实感情/恋爱阶段」的通用开源系统。

## 4. 如何替换当前模块

| 当前模块 | 研究改造方向 | 第一份应交付的证据 |
|---|---|---|
| `features/lexicon.py` 简单命中 | ConvoKit 中文特征 + 上下文判别，词表保留为透明基线 | 同一中文测试集的误报/漏报、反讽对照 |
| `llm/intent.py` 提示分类 | 中文上下文分类基线、DialogueGCN 对照、检索辅助 API 对照 | 逐类 F1、混淆矩阵、未来信息屏蔽测试 |
| 引用 ID 校验 | 原因/证据片段提取、支持度验证、反证和未知 | 片段定位成绩及人工支持度评审 |
| 固定 50/50 融合 | 根据验证集比较不同融合策略，不先认定固定平均最优 | 与当前融合的消融及分组误差 |
| `scoring/trend.py` 固定差值阈值 | 多变量变化点、个人基线与缺失度处理 | 人工标记变化区间上的检测误差、误报率 |
| 单一关系阶段/总分 | 证据化的多维互动描述 + 可确认阶段 + 明确不确定性 | 与当事人回访的对照；没有验证时保持产品指数标签 |
| 分析与回复割裂 | 统一结构化状态传给回复模型 | 回复是否遵循已经确认的情绪、边界和证据 |

用户提出的「85% 聊天证据、15% 辅助资料」保留为产品配置讨论项；论文不提供该比例的科学背书。辅助标签不混入训练/测试金标准，不给实验基线额外泄露答案。是否影响最终关系分仍待前一轮范围确认。

## 5. 本地与外部 API 路线

- **本地**：先比较中文编码器分类器与轻量说话人上下文模型，再加入证据片段抽取。通过显存/延迟实测选择部署方案。它是判断模型，和学习用户说话风格的个人回复适配器分别训练、评测与版本化。
- **外部 API**：共用标签、证据、时间范围与结果合同；允许在用户授权后发送的上下文中加入可追溯的中文标注示例。不同供应商分别评测，不把一种模型的结果归给另一种。
- **共用**：好友隔离、资料来源、证据支持、未知状态、媒体缺失状态、用户确认发送，以及同一测试集和报告方式。

## 6. 真正可复现的验收顺序

1. **任务定义**：先定义可观察的表达情绪、沟通行为和趋势；多标签、反讽、玩笑、拒绝与未知分别处理，不把「对方真实内心」直接作为可轻易标注的答案。
2. **资源锁定**：记录论文版本、代码 commit、依赖、数据/模型许可、预处理、训练参数、随机种子和硬件。
3. **原场景复现**：对一个许可明确的候选先复现原任务基线，记录与论文不同的设置及成绩差距。未复现时明确标「方法参考」。
4. **中文微信适配**：建议先建立约 1000 个带上下文的试验案例，两人独立标注、分歧裁决，并报告一致性；样本数量是试点规划，不是有效性的自动保证。
5. **防泄漏划分**：按好友对/人物隔离，再做时间向前验证。相邻消息、重复 OCR 屏幕和同一段对话不能横跨训练/测试；检索例库不得包含测试答案。实时任务禁止使用后续回复。
6. **同条件比较**：现有系统、简单中文分类器、说话人上下文模型、API 模型使用同一输入范围/标签体系。变化点单独测，不能只给总分掩盖某层退步。
7. **报告指标**：macro-F1、逐类 precision/recall、混淆矩阵、置信区间、证据片段质量、拒判比例、校准误差、延迟和显存。尤其单列「玩笑误判生气」「改期误判拒绝」等用户实际代价。
8. **候选上线**：先并行观察新旧结果，不直接覆盖当前结论；达标后提交证据和模型版本，由用户确认启用。退化可回滚。

一个用户的 1000 条聊天适合做个性化试点，不能单独证明对所有用户都有效。研究数据大、论文发表、GitHub 有星标都不能代替这一步。

## 7. 给用户展示什么，才能建立可信度

每个判断提供：用了哪些消息、方法及版本、当前场景的验证结果、备选解释、资料缺失和适用范围。将「论文报告成绩」「本项目复现成绩」「中文微信独立测试成绩」分开展示。未经证实不宣传「科学认证好感度」或「准确读懂对方内心」。

结论：优先路线为 **中文数据与说话人上下文建模 + ConvoKit 特征 + 原因证据抽取 + ruptures 趋势检测 + 独立校准**；关系解释层通过用户回访持续验证，而非用更复杂的包装替代实验证据。
