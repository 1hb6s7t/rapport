## 4. 关键合同与公式（必须逐字实现）

### 4.1 有效证据量与去重

```
N_eff = Σ_episode min(5, Σ_{i∈unique(episode)} q_i)
```
- 唯一键 = `(source_event_id, kind)`；同一事件的重复上传、转发、多个模型的重复解释只算一次。
- 只接受 `origin == "observed_chat"` 且 `confirmed == True`：**AI 草稿与公共参考例子不计入**。
- `q_i ∈ [0,1]`：归属正确、上下文完整、独立、已确认。
- 每个 episode 上限 5，是"防止高度相关消息刷样本"的工程假设，需评测后调整。

### 4.2 标签先验（本次唯一的方向反转）

```
alpha(N_eff) = 0.70 * exp(-N_eff / 40)
```
- 初始总先验预算 0.70，内部 MBTI 0.40 / 星座 0.20 / 属相 0.10；**剩余 0.30 是"未知空间"**，不是凭空造出的聊天证据。
- 某个标签缺失时，其权重进入未知，**不允许**把剩余标签放大到 1.0。
- 数值全部标注为"娱乐产品实验参数"，不是心理学常数。

**硬边界（不可协商）**：
- 标签只生成 `source_type=tag_hypothesis` 的**沟通风格假设**，可被推翻。
- 好感度计算**不接受任何标签输入**（`favorability_index` 签名里没有标签参数）。
- 没有聊天时：画像显示"初始画像/待验证"，好感度字段为 `null`，**不画第一个趋势点**。
- 界面文案必须写：标签仅作初识阶段参考，随真实聊天动态修正。

### 4.3 好感度聚合

```
S_obs  = Σ_j w_j s_j / Σ_j w_j          （仅对已观测维度求和）
S_prov = ρ*50 + (1-ρ)*S_obs             （ρ = 证据不足的收缩程度，与标签无关）
```
- 维度基准权重：回复积极性 0.25 / 情感温度 0.20 / 主动程度 0.20 / 投入深度 0.20 / 共同未来安排 0.15。
- 缺失维度为 `null`，**不补 0**；coverage 的分母是**全部基准权重**，不允许先把缺失项清零再算 coverage。
- 显示条件：`coverage ≥ 0.60` 且 `≥2 个独立上下文片段` 且角色确认通过；否则显示"暂不足以评分"及原因。
- 明确拒绝/停止联系/安全信号 → 主界面转为边界提示，**不显示分数**，不拿历史高分暗示继续。
- 输出恒带 `is_probability = False`；锚点 0/25/50/75/100。
- MVP 只展示 `S_obs + coverage + 暂定状态` 中的一个数字，不并列堆两个分；`S_prov` 先在调试面板做实验。

> 与现状的差异：本仓库 `COVERAGE_MIN = 0.70`，需下调为 0.60 并补"≥2 独立片段"门；新增 `S_prov`。

### 4.4 语义情绪分层合同（M03）

| 层 | 字段 | 说明 |
|---|---|---|
| 表层 | `literal_affect` | 字面情绪（如"我生气了"= 字面负向） |
| 语用 | `pragmatic_tags[]` | 真生气 / 撒娇假生气 / 调侃 / 反讽 / 委婉拒绝 / 寻求安慰 / 信息确认 |
| 情绪 | `emotions[]` | 不满 / 伤心 / 开心 / 担忧 / 亲近 / 混合 / 不确定 |
| 边界 | `boundary_status` | 无 / 明确拒绝 / 停止联系 / 需安全关注 |
| 解释 | `candidates[]` | 最可能解释 + 备选解释，不强制唯一答案 |
| 可信 | `evidence_strength`、`model_confidence_raw` | 证据充分性 **与** 未校准自评分开 |
| 来源 | `evidence_ids`、`counter_evidence_ids`、`reference_example_ids` | 用户聊天证据与公共类比证据**严格分开** |

- **多标签 + `ambiguous`**：真实生气与撒娇可能共存，禁止强制归入互斥三标签。
- 上下文管理：按话题/引用构造 episode；回复生成只用 `event_time ≤ as_of`；复盘模式可含后文但标记为"事后解释"，不冒充当时预测。
- 预算优先级（16K 示例）：任务/Schema 1.5K → 公共例子 2K → 当前 episode 6K → 引用与相关历史 2K → 旧画像/摘要 1K → 输出 2K → 余量 1.5K。**预算不足先削公共例子与摘要，绝不截掉明确拒绝证据。**

### 4.5 日记与记忆合同（M09）

`DiaryEntry` 字段：`id, revision, text, recorded_at, occurred_at, kind(fact|plan|feeling), enabled, allowed_relationships, approved_clause, deleted`。

必须实现的行为：
1. **检索后回查权威状态**：`authorize_memories()` 只接受 revision 匹配、未删除、已启用、关系在允许集合内、时间不倒流的条目；空 scope 默认不可检索。
2. **关闭即不检索**：`retrieve_if_enabled(False, retriever)` 不调用检索器（不是"检索了但不注入"）。
3. **时间一致性**：计划（plan）保持为计划，不写成已完成事实；`occurred_at > as_of` 不参与；`recorded_at > as_of` 不参与。
4. **严格模式**：`validate_exact_clause()` 要求短句"用户已批准 + 逐字存在于原文"；`strict_reply()` 只用固定模板 + 批准短句。**不做任意同义改写**。
5. **删除**：先阻断新读取与回写，再清来源/向量/摘要/报告；删除要有可验证的级联（含向量），并显示不可控范围。

### 4.6 本地模型调用加固（M14）

沿用参考代码的加固思路：模型白名单、`num_ctx` 边界（4096–16384）、**不继承代理、不跟随重定向**、响应体上限、`done_reason == "length"` 视为不完整输出、返回后仍需 Schema 与证据语义校验。

本仓库已实现的部分：Provider 抽象、脱敏、估价、内容哈希绑定的出网确认、截断识别与双倍预算重试、端点拒绝 `response_format` 时降级。

### 4.7 快照与趋势

每次用户确认导入后保存快照；曲线可升、可平、可缺失。**相同输入与版本不重复出点**；模型或规则变更时断线，或由用户主动重算历史；导入材料数量或窗口选择变化要在界面上显示。不把随机采样差异当关系变化。

## 6. 实测：上下文语义判断（今天用你的 Key 真实测得）

这一段是本方案里唯一的**实测数据**，直接决定了 M03 的设计。

**方法**：自编 20 组合成场景（无真实聊天），每组是同一句话配不同上下文，人工标注金标签；两种条件各跑一次——"给上下文"与"只给单句"。模型 `DeepSeek V4.1 Flash`（`api.example.invalid` 端点）。

| 指标 | 结果 |
|---|---|
| 带上下文正确率 | **9/20 = 45%** |
| 只给单句正确率 | 0/20（且 20/20 都回答"无法判断"） |
| 真实负面（7 例） | **2/7** |
| 真诚积极（7 例） | **3/7** |
| 反话（1 例） | 0/1 |
| 高置信度误判（≥0.70） | 2 例（0.72、0.78） |
| 输出非法 JSON | 1/20 |

**三个结论，直接改变设计**：

1. **"让模型给一个情绪标签"这条路单独走不通。** 45% 不足以支撑任何对外结论，而误判集中在最要紧的两类（真实负面、真诚积极）。
2. **模型有系统性偏向**：把大量中性/积极场景读成"敷衍冷淡"（p06/p11/p20 误判、p09/p16/p19 亦然）。若直接展示，会系统性告诉用户"对方在冷淡"——这是本产品最危险的失败模式。
3. **强制单选标签本身就是错的**：主报告 M03 要求多标签 + `ambiguous`，我的探针强制单一标签，实测把这个设计错误的代价量化了出来。

**因此 M03 的验收标准不是"标签准确率"，而是**：
- 是否在证据不足时**正确弃答**（单句条件 20/20 弃答，这一行为是好的）；
- 是否给出**正确的证据句**与**备选解释**；
- **负向判断是否需要更多证据**：负面/冷淡类结论要求跨 episode 的 ≥2 条独立证据才允许上浮到主界面（复用 §4.1 的 episode 封顶机制）；
- 高置信度误判率 ≤ 阈值（当前 2/20 不可接受）。

**下一步必须先做的两件事**（都在路线图 Phase 1）：给 20 组探针加**双人独立裁定**流程，把它变成可复现的评测集；再把公共参考样例做成 few-shot，测同一个探针看增益。

## 7. 我偏离主报告的地方及理由

### 7.1 暂不引入 LangGraph / Qdrant / BGE / Huey（D9）

目录把 R10 LangGraph、R15 Qdrant Local、R14 Sentence Transformers、R09 Huey 标为"直接采用"。我建议**先不引入**，理由：

- 现有 `JobRunner` + SQLite 状态表已实现检查点、中断对账、取消墓碑，73 项测试覆盖；换成 Huey 要新增一个进程与队列语义。
- 单用户日记规模（几千条）用 SQLite 存向量 + 余弦暴力检索足够；Qdrant Local 引入"同一路径只能一个 owner"的进程约束（NFR-06），对本项目是净增复杂度。
- BGE 需要额外 1–2GB 权重与下载步骤；本机 C 盘仅剩 18.7GB（见 §7.2），且 Ollama 自带嵌入端点可用同一条本地路径。
- LangGraph 的价值在多分支、人工介入、可恢复的复杂图；当前闭环是**确定的线性阶段**，用既有 pipeline + 显式状态机更小、更可测。

**保留接口**：`JobRunner`、`Embedder`、`Retriever` 三个接口已按可替换设计。触发条件写死在路线图里：当 Agent 循环出现 ≥3 条分支且需要人工中断点，或日记条目 >2 万时，按 ADR 重新评估。**这是一条你可以否决的决策**——若你希望现在就按目录采用，我需要额外 4–6 人天做集成与验证。

### 7.2 云 Key 与本地模型并存

按你的说明，AI 部分可以直接用 Key，因此：

- **开发与验证**：用已配置好的云端点（`DeepSeek V4.1 Flash`）直接推进，不等本地模型。今天已跑通：连通性 OK、JSON 调用 OK、`emotion_probe.py` 20 组对照实验完成。
- **发布默认**：仍是本地优先（需求约束 8），云调用保留既有"预览→确认→哈希绑定"闸门，**两个方向都不静默回退**。
- **日记外发单独确认**：日记比聊天更私密，M09/M10 的嵌入与生成默认走本地；一旦要发给云，必须单独弹确认，不复用聊天那次同意。
- 顺带修掉一个真实兼容问题：该网关按 `User-Agent` 拦截 OpenAI SDK 默认指纹（403），已在 Provider 中改为自报 `rapport/<version>`，并加了回归测试。同时注意**这个网关会注入它自己的系统提示**（回复里出现过它的自我身份），属于数据质量风险，评测时要记录。

### 7.3 OCR 保留 RapidOCR（D10）

PaddleOCR 在 Windows 依赖重、当时装不上；RapidOCR 已安装、纯 CPU、实测 3 张合成截图 34 条消息正确。代价是少了版面分析，气泡归属靠自研坐标聚类。若后续要支持更多版式，再评估 PaddleOCR。

## 8. 风险与非目标

| 风险 | 等级 | 应对 |
|---|---|---|
| 细粒度情绪误判（§6 实测 45%） | **高** | 多标签+弃答；负向结论要求 ≥2 独立证据；先做评测集再谈准确率 |
| 标签先验被当成"对方喜欢你" | **高** | 标签不进分数；无聊天则分数为空；界面与 README 双免责 |
| 记忆幻觉（AI 编造日记） | **高** | 严格事实槽位（逐字+已批准）；自由生成路径单独标注"未逐字核验" |
| 用户过度依赖分数 | 中高 | 覆盖度与弃答常态化；不推送焦虑型下降提醒 |
| 许可与数据 | 中高 | R22/R24/R25 明确不分发；公共例库只做导入适配器；发布前填许可清单 |
| 本地硬件不达标 | 中 | 云 Key 兜底；本机磁盘紧张，模型与数据放 G 盘 |
| 把假设当事实循环强化 | 高 | 证据账本 + 画像版本 + "为什么改变"可查 |

**非目标（明确不做）**：不抓取/解密任何平台数据库、不 Hook 客户端、不自动发送消息、不做账号体系/支付/云同步/社区/遥测、不理解语音视频内容、不训练模型、不宣称预测准确率、不做心理诊断或危机干预、不面向未成年人。
