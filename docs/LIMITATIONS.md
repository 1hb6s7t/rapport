# 已知限制（必须随发行一起阅读）

这份清单区分**已实测**、**已假设**、**未验证**。发行说明只应写"已实测"的部分。

## 1. 语义与情绪识别

| 项目 | 现状 |

## 2. 检索

- 参考例检索与日记检索都是**词法**（字符 bigram），不是语义检索。用词与原文不重合就检索不到——已有测试把这条限制固定下来。
- 没有向量库、没有 embedding 模型。方案里的 Qdrant / BGE 属于后续阶段；因此"删除时的向量级联"**当前无对象可级联**，删除测试只覆盖了实际存在的存储。

## 3. 标签先验

- MBTI 0.40 / 星座 0.20 / 属相 0.10（初始总预算 0.70，其余归"未知"与聊天证据）是**产品假设**，没有任何研究支持它预测恋爱结果。
- 先验**不进入好感度分数**（有测试固定），没有聊天时分数为空。
- 先验文案全部为本项目原创，且明确写成"待验证的假设"。
- **先验卡的"被支持/被推翻"是极性比对，不是验证（v0.6）**：每个 MBTI 类型 3–6 张卡，各指向一个沟通倾向的一极（`knowledge/prior_check.TENDENCY_POLES`）；"推翻"只说明模型观察到的倾向落在另一极，观察本身仍是模型输出。极性由关键词从标签措辞推断，措辞不含极性词时记"尚未检验"。计划里"用户对推翻判定合理 ≥80%"未测。
- **换措辞不算画像修正（v0.6）**：同一极的不同说法不再产生画像版本变化记录，只有极性移动才记；`persona.pole_stability` 是最近 3 版极性一致率，不是可信度。

## 4. 好感度与阶段

- 五维权重、锚点、覆盖度 0.60 门槛、≥2 独立片段门槛、稳定阶段要求（≥8 段会话 / ≥21 天）全部是**产品假设**，未做盲测校准。
- 分数是行为描述指数，**不是概率**，不预测关系结果。
- 阶段回退会被记录，但"回退"不等于关系一定在变差。
- **攻略的「预期反应」是模型或模板的假设（v0.6）**：每个选项列出的对方反应与含义没有任何实证，只是让用户在行动前想清楚"看到什么就停"。规则模式的 7 个情境模板由特征层触发，未做用户实验（计划里的"会照做/不会/看不懂 ≥80%"尚未测）。
- **边界是"当前状态"，只看材料末尾 30 天（v0.6）**。在作者的 9 段真实微信材料上（4.6 万条，2026-09-18）此前 7/9 段总分被一句一年多前的「想死你了」「不合适」隐藏；改为近期闸门后 7/9 出分、2 段仍因近期停止联系/安全词被隐藏。30 天是假设；更早的命中不丢弃，写在边界说明里。「想死你了/累得想死」这类口语已从安全词表排除，规则命中仍需人工核对上下文。
- **未读媒体不计证据（v0.6）**。图片/表情/视频/文件只保留占位，内容从未被读取，因此不再进入 `N_eff`；报告会写明有多少条未读。微信导出里平台自带的语音转写按文本处理。
- **主动提醒（v0.6）是拟人化推送**：三个状态量与全部参数是产品假设，未经任何用户实验；默认关闭，每天 ≤1 条，趋势下降时只关心用户自己、不报数字。它不是对方在想你的证据。
- **真实材料只跑过规则层**：上述 9 段的规则总分 53–65、覆盖 1.0，是行为统计不是好感度预测，也未与作者的事后感受对照（v0.6 阶段 C/E）。

## 5. 本地模型与平台

- **本地模型（v0.8 起可用，效果未证）**：`solo / split / lite` 三档走本机 Ollama（Qwen3 8B / 4B），零出网、不需要 Key；`rapport models doctor|pull|local-on` 与设置页卡片已跑通。
  **未做**：内嵌 llama.cpp 兜底（没装 Ollama 就没有本地 AI）；Schema 级约束输出（只有 Ollama 的 `format: "json"`）；bge-m3 本地嵌入（检索仍是字符 bigram）。
  **效果**：8B / 4B 在真实 300 条上的 macro-F1、稳定度、攻略存活率写在 `docs/EVAL.md` §16；跑不出来的项那里会写明原因。本机开发时因为系统提交内存长期接近上限（vmmemWSL + 其他进程），Ollama 加载 8B/4B/0.6B 都报 out-of-memory，**本地档位的效果评测在本机尚未完成**。
  **硬件下限没有测过**：doctor 的档位建议是按显存粗分（≥7.5 GB → solo，≥3.5 GB → lite），不是实测。
- RapidOCR 只在本机合成截图上验证过 3 张；**真实微信/QQ 截图的版式覆盖未验证**，低质量图会标为未知发送者并要求人工校正。
- Windows 上已验证；Linux / macOS **未验证**。
- Docker 镜像与 compose 未在本机实跑。

## 6. 关系档案与反馈（v0.4 新增，边界要说清）

- 关系档案只隔离**数据**，不做身份识别：同一个人被建成两个对象，或两个人被导进一个对象，工具都无从察觉。
- 用户反馈是**记录**不是训练信号：它不改分数、不改提示词；导出的评测用例标 `adjudicated: false`，未经人工裁定不得当金标签。反馈的选择偏差（用户更倾向对负面判断点 👎）尚未评估。
- 调用账本的费用是按预设单价估算，`usage` 缺失的端点记为未知；截断率是产品里首次可观测，但截断本身尚未消除。
- 证据质量 `q_i` 按时间精度与消息类型取 1.0 / 0.9 / 0.8 / 0.5，是产品假设，未校准。
- 第一人称事实核验是正则检测器（“我…去过/吃了/买了…”），只覆盖常见句式；漏检的编造仍可能出现，因此草稿永远是草稿。
- 端点硬化只对 IP 字面量判断内网/元数据地址；DNS 名解析到内网的情况不在检查范围内。

## 8. 明确不承诺

不预测准确率；不保证挽回或提升成功率；不做人格诊断或危机干预；不抓取或解密任何平台数据库；**不在无人操作时发送任何消息**。v0.7 起有一个可选的「粘贴到聊天窗口」（仅 Windows，默认关）：通过 Windows 无障碍接口把一条草稿粘进你**当前聚焦**的输入框，默认不按回车；「粘贴并发送」需要第二个开关，且每条仍要你单独点一次。它不读取聊天内容、不 Hook 客户端、不在后台运行；主动提醒本身从不调用它。
