## 1. 分期路线

### Phase 0 · 对齐与基建（3 人天）

**交付物**
- `/api/settings` 增加"本地 / 云"两档，明确展示当前链路与是否有静默回退（断言测试）。
- 好感度门槛按 §4.3 调整：`coverage ≥ 0.60` + `≥2 独立上下文片段` + 角色确认；`COVERAGE_MIN` 从 0.70 下调并补门。
- `message-v1` 增加 canonical event id 与重复导入去重；AI 草稿标记 `origin=ai_draft`（不进 `N_eff`）。
- `docs/` 落盘本方案与路线图；README 更新定位（纯个人开源、非营利）与免责声明。

**验收门**：无云 Key 时本地链路能跑通规则模式；有云 Key 时每次出网都能追到一次确认记录；重复导入同一文件不产生新证据。

---

### Phase 1 · M03 语义情绪最小闭环（9 人天）

**这是全项目最该先做、也最难的一块。**

**交付物**
- 分层 Schema（§4.4 的七个字段组）落进 `report-v1`，多标签 + `ambiguous`。
- episode 构造器：按话题/引用切分，保留目标句前文；回复生成只读 `event_time ≤ as_of`。
- 上下文预算管理器（16K 分档，超预算先削公共例子与摘要，**绝不截掉边界证据**）。
- 评测集：现有 20 组探针扩到 **≥60 组**，加**双人独立裁定**流程与 macro-F1 报告（只报分标签召回，不报单一总体准确率）。
- 公共例库：先只做**原创对照种子**（≥40 组）+ 适配器接口；CPED/MPDD/ESConv 暂不导入（许可未清）。
- few-shot 注入，并复测同一探针测增益。

**验收门（量化）**
| 指标 | 当前 | 目标 |
|---|---|---|
| 带上下文 macro-F1 | 未测（单一标签正确率 45%） | ≥0.70 |
| 高置信度误判（≥0.70 判错） | 2/20 | ≤1/60 |
| 证据不足时的弃答率 | 20/20（单句条件） | 保持 ≥90% |
| 非法 JSON | 1/20 | 0（一次修复重试后） |

**退出条件**：达不到目标就不进入 Phase 2 的"负向结论上浮"，改为只展示候选解释与证据，不给结论性标签。

---

### Phase 2 · M04 + M05 先验、权重与快照（8 人天）

**交付物**
- `prior_weight`、`effective_evidence`、`N_eff` 账本；标签先验 0.70（0.40/0.20/0.10）+ 未知 0.30。
- `ProfileReducer`：画像版本 +1、每条改动记"为什么改变"、旧版本可查与失效。
- `S_obs` / `S_prov` 两层；MVP 只展示一个数字 + coverage。
- 跨导入快照：同输入+同版本不重复出点；规则/模型变更断线或用户主动重算。

**验收门**：α 随 `N_eff` 单调衰减且可复算；AI 草稿与公共例子不增加 `N_eff`；无聊天时分数为 `null` 且不画趋势点；标签变更**不改动**已产生的分数与阶段。

---

### Phase 3 · M09 + M10 日记记忆与代回复（11 人天）

**交付物**
- 日记 CRUD + `revision` + `kind(fact|plan|feeling)` + 单条启用开关。
- 关系隔离（`allowed_relationships`，空 scope 不可检索）、时间一致性、删除级联（含向量）可验证。
- 嵌入与检索（本地优先；云嵌入单独确认），检索后回查权威状态。
- 代回复：2–3 条风格草稿、事实槽位、风险标注、**仅复制不代发**；严格模式只用"已批准且逐字存在"的短句；自由生成路径明确标注"未逐字核验"。

**验收门**（照抄参考代码的测试意图，扩展为集成测试）
关闭记忆 → 检索器零调用；修改日记 → 旧 revision 立即不可检索；R1 的日记不出现在 R2 草稿；计划不被写成已完成事实；编造短句被拒绝发布；删除后来源/向量/摘要全部不可读。

---

### Phase 4 · M06/M07/M08 画像、标签接线与攻略（5.5 人天）

**交付物**
- trait 带来源/反证/版本/变化原因；标签先验接到画像（不是分数）。
- 阶段状态机：陌生 → 初识 → 暧昧 → 确定关系 → 稳定；"确定关系"必须明确证据或用户确认。
- 攻略演进记录：策略随画像版本变化，可回溯"为什么这次建议变了"。

**验收门**：阶段跃迁有依据 id；拒绝/停止联系状态下只产出尊重边界类行动；标签改动只影响画像假设区。

---

### Phase 5 · M11/M13/M14 前端补齐、隐私与本地化（8 人天）

> **2026-09-15 决定：本地模型部分跳过。** 前端、隐私与删除级联已完成；Ollama/Qwen 的安装、离线验收与 Schema 约束输出不在本版本范围内，因此「本地优先」当前指「默认只用回环端点、不静默走云」，不等于「离线可用」。

**交付物**
- 新页面：日记、记忆管理、代回复、**画像动态面板**（权重变化 + 好感度趋势 + 阶段进度条）。
- 隐私：向量/摘要级联删除的可验证路径、许可清单（自有/依赖/权重/数据四张表）、断网验收。
- 本地化：Ollama 运行时 + 模型管理器 + Schema 约束输出；模型与数据放 G 盘；**断网仍可跑主链**。

**验收门**：断网跑通主链（模型已准备的前提下）；无 Key 时不发生任何云调用（抓包）；连续三日随聊天新增，画像与快照按真实增量更新。

---

### Phase 6 · 评测与发行（3 人天）

**交付物**：五类证据分开报告（规则 / 模拟 / 真实模型 / OCR / 用户实验）；兼容性矩阵只写实测平台；SBOM 与许可清单；`v0.2.0-beta` 发行说明只写实际支持项。

**不做**：不把 37 项参考测试或 73 项本仓库测试当产品效果证明；未测平台不列入正式支持。

## 3. 现在就该做的第一件事

按依赖顺序，Phase 0 的三项（门槛调整、canonical id、本地/云两档 + 无静默回退断言）是 1–1.5 天的活，做完立刻能让后续所有阶段的验收可复现。

**其次是 Phase 1 的评测集**：把 20 组探针扩到 60 组并加双人裁定，**先有尺子再改代码**——§6 的 45% 已经证明凭感觉调 prompt 不可靠。
