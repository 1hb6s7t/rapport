# 本地标注资料接入与版本化数据集

实现版本：`personal-dataset-v1`。这是数据审核、构建、复核和导出能力；它不代表候选论文已复现或新模型已达到上线标准。

## 资料来源与只读边界

默认读取 `D:/.rapport/eval` 下的 `redacted/*.json`、`annotations/<同名会话>/batch*.json` 和 `gold/cases-v2.json`。排除所有以下划线开头的文件；不读取别名映射、数据库、密钥、配置文件或媒体网络地址。路径越界链接会被拒绝。

当前 `annotations` 批次是标签来源，`semantic_review_version=context-v4` 优先。`cases-v2` 只记录来源哈希及历史映射分层，既不覆盖当前标签，也不成为独立测试集；不读取 `cases-v1` 或旧合并快照。包内固定词表映射来自项目 `docs/label_map_v2.json`，快照记录它的版本和内容哈希。

应用数据目录下的 `datasets` 独立于临时聊天 `blobs`。正文先压缩再通过现有 `Crypto` 加密，源路径只在加密审核快照内保存；公开清单只包含匿名会话标识、来源哈希、版本和汇总。构建使用审核时冻结的数据，即使原目录后来变化，也不会混入本次版本。修改复核结果会创建子版本，不覆盖旧快照。

源码目录及 `D:/.rapport` 不作为本次输出位置。命令行要求输出位于源目录和代码仓库之外；API 在源目录与输出目录重叠时拒绝操作。不存在自动上传调用。

## 三个用途及划分

- `offline_review`：28,019 条，保留后文证据及 `post_hoc` 标记；只有较高质量层默认可作为 AI 辅助监督数据，绝不称为人工金标准。
- `realtime_review`：13,799 条候选，输入仅含目标之前最多 12 条消息、同一连续会话；无显式后文证据仍不证明原标注过程未看过后文，因此全部默认 `training_eligible=false`，须逐项因果复核。
- `personal_reply`：5,113 条真实本人回复。上下文内至少有一条对方消息；过滤不可见媒体、系统／未知角色、空白、过长目标与标记为未确认的 AI 草稿。转写文本有 `from_voice` 标记；实际发出的文字也不自动视为人工审定的理想答案。

默认 `split` 是好友组隔离；会话组按开始时间及匿名标识排序。通过规范化的“发送者、时间、类型、内容”指纹识别重复导出，元数据改变的重叠导出仍放入同组。来源索引及内容指纹均校验跨集合泄漏。好友体量差异导致条数比例不一定为 70/15/15，报告会展示实际数量。

另提供 `time_split`：每位好友按时间顺序、完整六小时会话段划分，约 70/15/15。引用跨时间划分边界的样本标为 `excluded_boundary`，不作为该协议的训练／评测样本。实际隔离 50 条离线和 7 条实时候选；本人回复时间划分为训练 3,502、验证 710、测试 901。

**一次实验只能选一种划分协议，不能混用。** 前者验证未见好友适配，后者验证同一好友后续时间效果。两者均是已使用资料的开发回归；`independent_blind_test=false`。后续新增且未调参材料才可用于正式盲测。

## API 与使用方法

所有 `/api/datasets` 路由要求现有配对会话，写操作继续执行 CSRF 校验，响应使用 `Cache-Control: no-store`。

| 方法 | 路由 | 行为 |
|---|---|---|
| GET | `/datasets` | 返回 `{items: [manifest]}` |
| POST | `/datasets/audit` | `{source_root}`，冻结加密审核快照 |
| POST | `/datasets/build` | `{audit_id}`，生成独立数据集版本 |
| GET | `/datasets/{id}` | 清单、来源、质量、用途及划分统计 |
| GET | `/datasets/{id}/preview` | `pool/page/page_size`，最多100条，展示上下文、标签及复核状态 |
| POST | `/datasets/{id}/reviews` | `{pool,sample_id,decision:"accepted"或"excluded",note?}`，创建子版本；不能接受不可见媒体或空映射标签 |
| POST | `/datasets/{id}/export-preview` | `{pools:[...]}`，返回所选文件清单、条数与十分钟确认令牌 |
| POST | `/datasets/{id}/export` | `{token,confirmed:true}`，仅下载所选用途的 ZIP，不上传；检查快照及令牌一致性 |

复核实时候选表示用户已结合所显示的前文确认标签，才置 `human_confirmed=true`、清除 `causal_review_required` 并允许训练。一次复核只作用于选定用途，不把离线审阅自动转为实时金标准。

导出内容是匿名 JSONL 与清单，没有联系人文件名、身份映射或配置。它仍包含用户选中的脱敏聊天原文，外发前需再检查具体内容；导出不等于允许外发。

后台任务可复用 `DatasetStore(data_dir / 'datasets', crypto)` 的 `audit(source_root)`、`build(source_root=None, audit_id=...)`、`get(id)`、`list()`、`records(id,pool)` 接口。训练代码必须尊重 `training_eligible`、质量层与选择的划分协议，不可自行把所有记录升格为金标准。

本地命令示例（路径按实际应用数据目录调整）：

```powershell
python scripts/prepare_personal_dataset.py --source-root D:/.rapport/eval --data-dir C:/private/rapport-data --build
```

脚本只打印汇总，使用应用同款 `.key`，不会读取源目录里的密钥。

## 验证及限制

14 项合成数据测试覆盖：源目录只读、别名文件不读取、冻结构建、弱标签与后文隔离、本人目标过滤、好友及时间划分无泄漏、重叠导出归组、密文校验、明确确认导出、令牌过期、不可变复核、配对及 CSRF、分页。代码静态检查通过。

当前复核支持接受／排除现有固定标签；尚未提供手工重写词表及标签的界面。媒体原文件不会由数据集模块自动寻找或下载。长任务调度、训练、模型选择和启用由独立学习模块承担。

## 已确认归档的增量更新（P7）

调用 `rapport.datasets.archives.append_authorized_archives(state, relationship_ids=[...], base_dataset_id=..., archive_ids=..., now=..., relationship_session_map=...)` 创建不可变子快照。`relationship_ids` 必须显式指定，`archive_ids` 可进一步限制本次范围；不会读取未授权好友。仅使用长期归档服务已确认保存的微信导出或 OCR 可见聊天。粘贴文本、通用 JSON 等无法证明是实际已发聊天的来源不会自动进入表达训练。

仅接受秒或分钟级可靠时间、明确双方发送方向、已观察的文字正文。未知时间导致整份归档暂缓，因为无法正确排列其与其他导出重叠的位置；逆序时间同样暂缓。媒体、系统／未知角色、引用内容未明、标记为 AI 草稿或未发送草稿的文字均打断上下文，不把这些记录拼入后续训练目标。

会话按六小时无交流间隔分段；结束不足六小时的会话先等待封口。重复导出通过有时间的内容指纹去重。部分重叠需要至少三条顺序一致的锚点；同一精度时间下存在无法定位的新行、重复内容次数不明时暂缓，不能擅自猜测其顺序。来自同一好友的上下文才能组合。

归档更新采用固定会话分桶，约 70% 训练、15% 验证、15% 测试；已存在样本与分区不重排。首次增量快照记录前瞻起点，此后新会话中分到测试的样本标记 `prospective_holdout=true`、`training_eligible=false`、`evaluation_eligible=true`。测试留出永远不因后续刷新或“接受标注”而转入训练；这只表示已预留后续独立验证材料，未宣称已完成人工盲测。

对于先前脱敏的9组会话，不通过名称猜测它们对应当前哪个好友。可以显式提供 `relationship_session_map={内部好友ID:已有匿名会话ID}`；自动关联只接受至少三条连续消息的顺序、精确时间、正文及双方角色均吻合，并且只对应一组旧会话的情况。仍不明确时，新候选只保存在密文待复核区。已关联旧数据集的好友延续原好友分区；新材料与旧完整会话重叠但无法保证边界时也暂缓。因此，自动试点可以先用独立的归档数据集，待映射确认后再合并旧资料。

返回清单的 `delta.new_eligible` 只统计新增可训练且位于训练分区的本人回复，用于“新增200份合格样本”阈值；`new_samples` 包括训练／验证／测试，另显示 `new_forward_holdout`、`pending_binding`、`pending_overlap`、`open_conversations` 及时间／来源排除数量。无变化返回原版本及 `unchanged=true`，旧密文与清单不改动。

真实内部好友及归档撤销关联保存在密文 `archive_bindings`、`sample_archive_sources`。训练工作进程使用 `learning_source_bindings(store, dataset_id, sample_ids=实际使用样本)` 获取 `relationship:...` 和 `archive:...`，合入模型来源索引；此数据不会出现在导出 JSONL。该方法默认只读当前应用的归档索引，确认来源仍存在且属于原好友；来源删除后拒绝新训练登记。撤销操作可以使用 `verify_present=false` 查询已删除来源的原始关联。删除来源并不等同于已训练模型自动遗忘，应撤销模型并重新训练。

增量专用测试覆盖显式授权、跨好友隔离、实际本人目标、未知时间与草稿过滤、重叠归档去重、模糊重叠隔离、会话封口等待、重复更新幂等、旧快照不变、前瞻测试冻结、脱敏旧好友映射、临时导入过期兼容，以及来源删除后阻止续建和训练登记。源 `D:/.rapport` 未被此适配模块读取或写入。
