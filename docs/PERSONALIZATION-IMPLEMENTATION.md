## 已实现的模块

### P0 / P2：数据接入、质量检查与复核

`rapport.datasets` 提供只读审核、不可变加密快照、分区校验、预览、复核和确认导出。源文件变更后，可从以前批准的源目录构建新版本；未变化时不重复生成快照。

导出可进一步选择匿名对象、会话、划分、样本 ID、质量条件和数量上限。预览固定所选记录、顺序、校验值、浏览器会话和目标环境；导出不含来源路径、私有关系绑定或身份映射。

已修复回复材料跨好友引用、未确认材料用于回复、好友切换残留，以及目标、风格、生日档案修订后预览仍有效的问题。任务级实际模型与预览中的模型一致。

### P1：档案与长期归档

生日包含公历/农历、年/月/日精度、闰月、来源、确认状态和修订号。不补齐未知部分，不在未核验历法算法时猜测属相或星座。

长期归档与 24 小时临时导入分离。聊天、媒体和元数据加密；大媒体分块校验。明确区分原件、缩略图、缺失状态。确认后导出 JSONL、媒体清单、可离线打开的 HTML 查看器及所选媒体。

现有 eval 目录没有媒体原件。新媒体可从用户选定文件或微信另存为流程取得，屏幕缩略图不充当原件。

### P4：分析状态与回复

新增版本化 `analysis_context`，包含好友、材料摘要与范围、档案修订、分析器版本、证据、历史检索及不确定性。回复仅检索同一好友且时间可见的历史。没有可见上下文契约的旧标签，以及未来证据，不被冒充实时判断。

85% / 最多 15% 是产品解释和回复排序的约束，不是论文测得的心理学权重。客观关系评分仍只取聊天证据；模型自报匹配度明确标记为未校准，不展示成喜欢程度概率。

**尚未完成**：经过有效评测的新情绪/意图/证据模型替换现有分析器。目前报告中回顾性判断不会强行移用到实时回复。

### P5：真实训练、评测与版本管理

独立子进程执行训练与评测；持久化任务支持进度、取消、重试、中断识别、候选登记、比较、确认启用和回滚。模型权重加密保存，启用必须通过门槛。清空资料会先停止训练，再清理私有模型与快照。

已实现两个真实字符统计分类基线，以及本地 PEFT LoRA 训练、独立回复评测和本地适配器调用路径。分类基线不冒充中文预训练编码器或论文复现。

个人回复已改为三个短句并行生成、程序封装结构，并修正中文风格名与英文枚举不一致的问题。独立 worker 缓存 CPU 权重，每次请求独占 GPU，用完移回 CPU；不再每次请求重启并重新加载模型。实际编译后的提示、顺序、生成预算、模型和事实校验策略都进入预览签名。模型登记信息、权重、评测样例均加密；样例复核绑定其内容哈希，重新评测后旧复核不能放行新结果。

个人模型学到的表达不被视为本次已授权事实。检测到无依据的本人经历时，草稿被隐藏且不进入发送；资料不足时允许明确拒答。自动可用性门槛要求至少 90% 测试组仍有可用候选，这属于产品覆盖率约束，不是事实准确率。原始风险数量、过滤数量和拒答数量分别报告。逐条样例标注保留为可选的严格质量复核；自动检查通过后，用户也可在清楚显示局限的确认框中选择本机试用，随时停用。试用不会被记成人工质量审核通过，不能绕过自动失败或用户已给出的否定复核。

独立训练环境使用 PyTorch 2.6.0+cu124、Transformers 4.51.3、PEFT 0.15.2、Accelerate 1.6.0。通过 `RAPPORT_TRAINING_PYTHON` 指定其 Python，不要求将训练依赖装入 OCR 服务环境。本地基座在应用目录 `learning/base_models/` 下注册；训练及推理都使用本地文件且禁用远程代码与在线下载。

### P6：有序消息预览与执行

文字、表情和图片使用有序项目与素材 ID。预览绑定接收人、聊天上下文、项目顺序和素材校验值。确认后逐项记账；不确定结果不自动重发。回复页支持调整已有项目顺序或移除素材，并查询回执。

**支持范围**：原生驱动实现了文字、PNG/JPEG 和有确切原件的 GIF 核验路径；GIF 必须匹配至少两个不同帧。微信表情面板另新增关键词搜索→可见候选→具体图片预览→单张确认发送路径，先读无障碍名称，只对选中的名称笼统项做轻量小图 OCR；不会仅凭关键词自动点击。已完成文件传输助手的文字填入、读回、撤销及真实捕获→合成归档→媒体上传→整组预览。首次获准实发在身份前置核验失败，未填入；改为双无障碍姓名核验后，第二次获准实发通过完整预检，但文字填入后发生焦点变化，发送按钮未点击，合成草稿已清除，PNG/GIF 未执行。两次单次授权都已消耗，不会重试。表情搜索已在真实微信做只读候选验收；表情点击、图片、GIF、原件另存为和发送后回执尚未完成实机闭环；详见 `MEDIA-DISPATCH.md`，不宣称全版本兼容。

### P7：默认关闭的更新任务

开启后每日只读检查选定来源，每周检查新增合格样本门槛（最低 200），创建候选训练并接续评测。支持分析基线或个人表达适配器；新模型不自动启用。GPU 锁覆盖本地训练、生成及 OCR，冲突时明确返回忙碌状态。

已接入明确授权好友的已确认长期归档，按完整会话去重，冻结前瞻留出集；缺失时间、未知媒体、草稿和无法安全关联的旧来源进入排除或待复核层。每日持久化整理作业、每周新增合格训练样本检查、训练→评测均可追踪和取消。消耗记录按实际参与训练的样本 ID 记账，128 条预算不会消耗全量资料；改快照名不能重复触发同一批训练。支持本地时区，来源删除会撤销关联模型。

**保留边界**：不自动切换用户的微信窗口采集；目前使用已确认的归档。GPU 有互斥但没有任务优先级抢占。跨用户和新盲测数据验证尚未完成。自动更新保持关闭。

### 16GB 显卡上的 Qwen3-8B 4 位（QLoRA）候选（2026-09-28）

基座：Qwen3-8B（Apache-2.0，修订 `b968826d`，5 个权重分片逐一核对官方 SHA-256），用 bitsandbytes 0.50.2 存成 4 位 NF4（双重量化，bf16 计算）后注册为 `qwen3-8b-nf4`（5.67 GiB）。训练时基座冻结在显卡上，只训练 LoRA；常驻推理同样以 4 位加载。同期的 Qwen3.5-4B/9B 是带视觉部分、混合线性注意力的新架构，配置要求 transformers 4.57 以上，训练环境是 4.51.3，升级会牵动已验收的训练和推理链路，本轮没有用；Qwen3.6/3.8 的小尺寸只有 27B 及以上，16GB 放不下。

依据前几轮的失败类型改了数据和提示，不只是换大基座：
- 训练和生成都给模型看同一好友以前的真实回复（与风格检索同一套检索，最多 8 条）；训练样本只看比自己更早的回复，128 组测试的 1,024 条示例都早于对应测试组。

- 第二轮起，陈述本人状态、计划、行踪或持有物的回复不参与拟合：1,383 条里有 188 条，其中只有 1 条能从上下文推出。
